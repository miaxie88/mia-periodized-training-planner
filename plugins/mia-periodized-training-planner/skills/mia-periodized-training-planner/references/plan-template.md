# 周期化训练计划交付模板

按任务规模使用。解释方法时不必填完整模板；交付 4–16 周计划时应包含全部核心段落。

## A. 结论先行

用 3–5 句说清：

- 主目标；
- 最大限制因素；
- 计划分成几块，为什么按这个顺序；
- 训练主轴和维持项；
- 最重要的安全或执行边界。

## B. 假设与安全边界

```markdown
### 已知信息
- …

### 当前假设
- …

### 仍缺失、会改变计划的信息
- …

### 不适用/需先评估的情况
- …
```

如果用户已提供完整资料，不用重复大段抄写；只保留会影响处方的信息。

| Defender 2 | 证据 + 与主目标的关系 |  |  |  |

## H. 反馈与自动调整

```markdown
### 进阶
当……时，下周只增加……

### 保持
当……时，原负荷重复……

### 回调
当……时，优先减少……

### 停止与转介
当……时，停止并……
```

加一个每周 2 分钟复盘：

1. 我完成了多少？
2. 同样用力下，表现有没有变好？
3. 有没有新疼痛或恢复恶化？
4. 下周是进阶、保持还是回调？

## I. 评估与下一周期

结束时对照：

- 主指标是否改变；
- 哪个 defender 被证实/被否定；
- 哪个阶段出勤或恢复最差；
- 哪种负荷杠杆最有效；
- 下一周期是继续主目标、转向新目标，还是先恢复。

不仅根据最后一次测试判定成败。同时看趋势、完成率、技术质量和代价。

## J. 计划审查时的简化输出

审查现有计划时，先给：

1. 最大亮点；
2. 最大结构问题；
3. 最值得保留的设计；
4. 最该删除或合并的部分；
5. 三个最高优先级修改；
6. 修改后的块架构和一周示例。

不在结构问题尚未解决时，花大量篇幅替换小动作。
